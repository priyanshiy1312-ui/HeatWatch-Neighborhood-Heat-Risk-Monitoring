# HeatWatch: neighbourhood heat and water-stress early warning

Built for Environmental Hacks (Bharat Builds Tour), Heat and Water track. Pilot city: Jaipur.

City-wide heat alerts are too coarse. HeatWatch scores each neighbourhood for heat risk and water stress, recommends concrete actions for officers, and sends Hindi/English alerts.

## Features
- Heat risk, water stress and priority score per ward, with an explainable breakdown
- Interactive map with 3-day forecast selector and top-5 officer list
- Action recommender (cooling shelters, tankers, work-hour changes)
- Hindi/English advisories from Amazon Bedrock, with offline template fallback
- Alerts through Amazon SNS with DynamoDB de-duplication, run on a 3-hour schedule
- Works offline for demos (`HEATWATCH_OFFLINE=1`): labelled sample forecast and resources

## Run locally
```bash
cd backend && pip install -r requirements.txt
python -m pytest                          # 16 tests
uvicorn app.main:app --reload --port 8000
# new terminal
cd frontend && npm install && npm run dev  # http://localhost:5173
```
Optional: `HEATWATCH_OFFLINE=1 uvicorn ...` for a fully offline demo.

## API
`GET /api/health` · `/api/wards?day=0..2` · `/api/wards/{id}?day=` (scores, actions, 3-day trend) · `/api/wards/{id}/advisory?lang=en|hi` · `/api/top` · `/api/resources` · `POST /api/alerts/send/{id}` · `POST /api/alerts/check` · `GET /api/alerts/log`

## Data and limitations
Ward shapes and values (green cover, population, vulnerability, water points) are labelled SAMPLE proxies generated by `scripts/build_sample_data.py`, not official ward data. The forecast is one point at the city centre. Replace the data files with real ones to go beyond the demo. This is a decision-support prototype, not a medical or emergency system.
